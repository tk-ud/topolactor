## 暫定対応方針

- Test hardening scopeとして production runtime read-source 本体は変更せず、DBなし fast lane のテスト面と seed fixture を補強した。PR537 auditで user-facing render 断線を test が露出したため、許容された最小修正として `ProjectionView` / `emissionSummary` に `projectionDefinition` 消費と user-facing summary 表示を含めた。追加で `db/demo_seed.sql` の seed manifest `00000000-0000-0000-0000-000000000085` を実際に backend runtime 本線へ通す collapse test を追加し、同一 manifest identity が ScreenDataShapeQueryRuntime / emission.Data / db_notify / SSE まで届くことを検査した。
- `projectionLaneSeedHarness.test.ts` で SQL seed を静的 parse し、demo/admin 対象 manifest ごとに mapping contract を検査し、抽出した `initialDataRows[0].values` を lane harness に流して `projectionFromEmission` と `projectionRuntime` の projection assertion まで到達させる。
- `seedData ?? null` は使わず、seed 欠落は NG test で明示 failure として扱う。literal fixture は `explicitLiteralFixture` という名前で保持し、seedData present path と混同しない assertion に限定した。
- GitHub Actions に backend lane / frontend lane / frontend user-facing render / seed contract / seed-to-lane integration を分離した job 名で追加し、backend lane job は `ManifestDispatcherManifestDrivenTests` 内の seed collapse test も実行するため、落ちた場所を CI 上で切り分けられるようにした。
- 追加テストの error message は `lane`, `seed`, `manifest`, `target/layer/action`, `mapping` を含むようにした。

## issue 実装時のok軸

- Backend lane: `ManifestDispatcher` が manifest topology の `projection_constructor_mapping` から `Emission.ProjectionDefinition` を注入することをテストで検出可能にした。さらに seed manifest `00000000-0000-0000-0000-000000000085` の dispatcher axes を入口に、`RuntimeExecutor` が同一 manifest id で `ScreenDataShapeQueryRuntime` を呼び、`screen_data_shape.initialDataRows` を `emission.Data.rows[0].seedLabel` に反映することを collapse test で固定した。
- Output/SSE lane: 同一 manifest id の成功 emission から `OutputLaneRouter` が db_notify payload identity を生成し、その manifest id を db_notify hook request として `ManifestDispatcher` -> `SseProjectionRuntime` -> `SseEventBroadcaster` へ渡すことを backend collapse test で検査する。Frontend lane: SSE receiver / dispatcher / projection runtime / render helper が projectionDefinition を消費する経路を既存 `sseLane.test.ts` と workflow job で実行する。
- Seed contract: `db/seed_empty.sql` / `db/demo_seed.sql` を DB 接続なしで静的 parse し、必要 mapping と `screen_data_shape.tableRef` / physical table / wiring seed の整合を確認する。
- Seed-to-lane integration: seedData を loop で lane harness に投入し、projection assertion まで到達する。
- PR537 auditで user-facing render 未検査が追加 Error として確認されたため、`ProjectionView` と `/demo` の `UserDemoStepper` → `UserDemoResultCard` が `emission.projectionDefinition` を消費しない場合に fail する DOM/SSR test を追加した。test が露出した user-facing render 断線には、回帰修正ではなく最小接続として `ProjectionView` と `emissionSummary` を更新した。現時点で追加 test は pass しており、今後この test が runtime read-source / frontend render / canonical projection consumer の別断線を検出した場合は、本bundle内で雑に直さず、次 bundle / issue として分離する。
