## Bundle `ui-builder-preset-ecosystem`

**Status:** partial
**Roadmap bundle:** `product.admin_topology_authoring`
**SSOT:** `docs/design/admin-console-workflow-ssot.yaml` (`ui_builder_canvas_workspace.authoring_flow.responsibilities.preset_ecosystem`)
**Supporting SSOT:** `docs/design/ui-builder-seed-first-gap-discovery-ssot.yaml`, `docs/design/mock-preset-intake-compiler-ssot.yaml`, `docs/design/runtime-orchestration-ssot.yaml`, `docs/design/pipeline-continuity-ssot.yaml`, `docs/design/sql-attention-logs-ssot.yaml`, `docs/design/ui-ux-primitive-catalog-ssot.yaml`

UIBuilder preset ecosystem parent surface is partial. Provisional preset surfaces remain tracked at bundle level until implemented or explicitly completed/descoped by SSOT. The design direction is seed-first preset SSOT: reusable preset contracts must be defined as SSOT-backed seed surfaces, not hardcoded active topology or one-off screen implementations. Preset seeds are also an audit surface: they must make missing UI wiring, missing component primitives, invalid parent/child structure, and broken payload bindings visible before active topology apply.

- [ ] `preset_ssot_seed_contract`: **Problem:** `aggregate_dashboard` / `physical_search_crud_aggregate` / `physical_details_inline_editor_md_generator` are named as provisional preset surfaces, but their UI placement and contents wiring contract is not yet specified deeply enough for audit. **Purpose:** make seed化 / preset SSOT化 the canonical design boundary while keeping business logic in contents, and make the seed reveal whether required UI wiring is missing or component structure is broken. **Improvement direction:** either create a dedicated preset ecosystem SSOT or extend the existing admin-console + seed-first SSOTs with per-preset contract blocks for layout tree, component catalog dependencies, contents topology name, assigned contents operation refs, payloadFrom shape, logs.diff history binding where applicable, preview/validate/apply boundary, and compile-time/audit checks for missing wiring and invalid component hierarchy. **References:** `docs/design/admin-console-workflow-ssot.yaml`, `docs/design/ui-builder-seed-first-gap-discovery-ssot.yaml`, `docs/design/mock-preset-intake-compiler-ssot.yaml`. **Targets:** `docs/design/admin-console-workflow-ssot.yaml`, `docs/design/ui-builder-seed-first-gap-discovery-ssot.yaml`, optional new `docs/design/ui-builder-preset-ecosystem-ssot.yaml`, `.agent/docs/ssot-map.yaml` / design index if a new SSOT is added.
- [ ] `hub_search_entity_wiring_alignment`: **Problem:** `hub_search.readonly.v1` is only a seed, but its wiring candidate currently points to `targetSurface: hub`, `targetRef: hub:search`, and `payloadFrom.query`; the existing runtime already has `content_bundle:search` using entity/content bundle search payload fields such as `keyword`, `kind`, and `state`. **Purpose:** prevent a pseudo hub-search operation from becoming canonical when entity/content search wiring is enough. **Improvement direction:** audit whether `hub:search` is SSOT-authorized; if not, update the hub search seed and tests to target the existing entity/content search operation (`content_bundle:search` or contents topology assigned search ref) and map `node:hub_search_input.value` to the expected search field, without creating hub-search-specific runtime logic. **References:** `db/migrations/hub_search_preset_seed.sql`, `backend/runtime/AdminRuntime.cs`, `backend/repository/ContentBundleRepository.cs`, `docs/design/admin-console-workflow-ssot.yaml`. **Targets:** `db/migrations/hub_search_preset_seed.sql`, `frontend/tests/mockPresetIntake.test.ts`, preset SSOT block, payload resolver tests if needed.
- [ ] `runtime_event_payload_binding_from_node_and_event_values`: **Problem:** preset actions cannot reliably dispatch runtime payloads from current node/interface values and event payload values. **Purpose:** make seed preset actions executable without screen-specific hardcoding. **Improvement direction:** implement a reusable `payloadFrom` resolver for `node:<nodeId>.value`, `event.item.id`, `event.row.id`, `event.record.id`, literals, and structured unresolved-ref errors; no silent fallback. **References:** `docs/design/ui-builder-seed-first-gap-discovery-ssot.yaml`, `docs/design/runtime-orchestration-ssot.yaml`, `db/migrations/hub_search_preset_seed.sql`. **Targets:** `frontend/runtime/*payload*resolver*.ts` or equivalent new runtime helper, `frontend/runtime/layoutComponentPreview.ts`, `frontend/components/FlowLayoutCanvas.tsx`, `frontend/islands/UiBuilderAdmin.tsx`, `frontend/tests/mockPresetIntake.test.ts`, new focused resolver tests.
- [ ] `physical_search_crud_aggregate_seed`: **Problem:** CRUD aggregate preset remains provisional, but its responsibility is UI placement and contents wiring rather than CRUD runtime implementation. **Purpose:** place a reusable list/search/create/edit/remove/detail UI shell that calls already-assigned contents operations. **Improvement direction:** seed a canvas preset with search input + search button, add button → modal → form, enum/status select generation, `card_list` rows, details/edit/remove buttons, confirm dialog reuse, tree/tree-node data binding, and node history drawer action; wire each action to the contents topology's existing list/search/create/edit/remove/detail operation refs through `payloadFrom`. Seed compile/audit tests must show whether any required UI wiring is absent or any component structure is invalid. Do not create a parallel CRUD backend or one-off screen runtime. **References:** `docs/design/admin-console-workflow-ssot.yaml`, `docs/design/ui-ux-primitive-catalog-ssot.yaml`, `docs/design/sql-attention-logs-ssot.yaml`. **Targets:** preset SSOT block, `db/migrations/*physical_search_crud*_preset_seed.sql` or existing preset seed registry path, `frontend/tests/mockPresetIntake.test.ts`, seed compile/preview tests, `frontend/components/catalog.ts` only if a required primitive is missing.
- [ ] `physical_details_inline_editor_md_generator_seed`: **Problem:** details preset remains provisional, but its responsibility is detail UI placement and wiring to existing contents detail/edit/history/PDF-preview capable surfaces rather than a new detail runtime. **Purpose:** provide a reusable details surface fed by CRUD card/detail selection. **Improvement direction:** seed header back button + PDF export preview, main tabs, tab1 two-column label/value grid with inline editable fields and enum/status selects, tab2 latest field history list, full-history side drawer, and document canvas preview/export snapshot wiring; map selected record id and field edits to the contents topology's assigned detail/edit/history operation refs through `payloadFrom`. Seed compile/audit tests must show whether any required UI wiring is absent or any component structure is invalid. Do not implement bespoke detail CRUD logic inside the preset. **References:** `docs/design/admin-console-workflow-ssot.yaml`, `docs/design/ui-ux-primitive-catalog-ssot.yaml`, `backend/runtime/PdfExportSnapshotRuntime.cs`, `frontend/components/DocumentCanvasTemplateEditor.tsx`. **Targets:** preset SSOT block, `db/migrations/*physical_details*_preset_seed.sql` or existing preset seed registry path, `frontend/tests/documentCanvasCatalogCheck.test.ts`, `frontend/tests/mockPresetIntake.test.ts`, details seed compile/preview tests, `frontend/components/catalog.ts` only if a required primitive is missing.
- [ ] `logs_diff_record_history_binding`: **Problem:** physical record history UI is designed around `logs.diff`, but preset read binding/history drawer contract is not fully captured as a preset requirement. **Purpose:** show latest field history and full field history without confusing `logs.diff` with topology definition audit logs. **Improvement direction:** bind history buttons/drawers to physical-table record lifecycle diff evidence (`create`, `update`, `logical_delete`, `restore`, `physical_delete`), preserve `logs.diff` as physical mutation pressure source, and prohibit direct reuse of `topology_edit_log` for physical record history. **References:** `docs/design/sql-attention-logs-ssot.yaml`, `backend/repository/SqlAttentionLogsRepository.cs`, `backend/repository/NpgsqlSqlAttentionLogsRepository.cs`. **Targets:** backend read API/repository method if absent, preset seed wiring candidates, `frontend/tests/mockPresetIntake.test.ts`, backend repository tests for history read boundary if implemented.
- [ ] `existing_entity_validate_save_dispatch_alignment`: **Problem:** CRUD/detail preset must use contents-assigned list/search/create/edit/remove/detail/aggregate operations and existing entity/draft dispatch where applicable; it must not create a parallel hardcoded CRUD runtime. **Purpose:** keep mutation flow aligned with contents topology operation wiring and existing content bundle entity lifecycle. **Improvement direction:** document and test preset wiring for validate→save/update draft→promote/save active entity using existing `content_bundle:*` dispatch or contents topology operation refs where applicable; if a required contents operation ref is absent, add SSOT/TODO contract before implementation rather than inventing a private route. **References:** `backend/runtime/AdminRuntime.cs`, `backend/repository/ContentBundleRepository.cs`, `backend/repository/NpgsqlContentBundleRepository.cs`, `docs/design/runtime-orchestration-ssot.yaml`. **Targets:** preset seed wiring candidates, `frontend/lib/packageWiringOptions.ts`, `frontend/lib/packageWiringPicker.ts`, `frontend/tests/mockPresetIntake.test.ts`, backend dispatch tests only if new dispatch names are added.
- [ ] `aggregate_dashboard_seed`: **Problem:** aggregate_dashboard remains provisional, but UI preset responsibility is limited to condition input and result display. **Purpose:** let authors specify a contents topology name, bind one or more contents-side aggregation functions, and render the returned label/data pairs as a reusable dashboard preset. **Improvement direction:** keep aggregation logic in contents-side topology/function wiring; UI preset supplies only search input, start/end inputs, status checkbox filters, grid display frame, and label/data display nodes. The seed must map `contentsTopologyName` + `aggregationFunctionRef` + filter node values to existing display components through preview/validate/apply, and compile/audit must expose missing wiring or invalid component hierarchy before apply. **References:** `docs/design/admin-console-workflow-ssot.yaml`, `docs/system-roadmap.yaml`, `docs/design/ui-ux-primitive-catalog-ssot.yaml`. **Targets:** contents-side aggregation function wiring surface, preset SSOT block, optional seed migration/tests, `frontend/tests/mockPresetIntake.test.ts`, `.agent/tasks/todo.md` status update after audit.

Note: `hub_search.readonly.v1` is now registered by `db/migrations/hub_search_preset_seed.sql` as a UIBuilder canvas preset seed composed from existing component catalog entries only; it is not a new component implementation and does not write active topology.
